# Открытые вопросы, проблемы и баги проекта Senio

Живой список того, что ещё не решено, сломано или требует внимания.
Документ существует, чтобы такие пункты не терялись в больших
документах ([`docs/project-context.md`](project-context.md),
[`AGENTS.md`](../AGENTS.md)) и в истории переписок.

## Идентификация пунктов

Каждому пункту присваивается постоянный идентификатор:

| Префикс | Категория | Пример |
|---|---|---|
| `Q-` | Открытый вопрос (архитектура, продукт) | `Q-001` |
| `P-` | Известная проблема или ограничение | `P-001` |
| `B-` | Известный баг | `B-001` |

Номера не переиспользуются: закрытый пункт освобождает свой номер
навсегда. Идентификаторы действуют только внутри репозитория: GitHub
не распознаёт их автоматически. Если для пункта нужно автоматическое
закрытие через PR, заведи под него Issue и укажи его номер в строке
пункта, а ссылку на идентификатор добавь в текст Issue.

## Правила ведения

1. Каждый пункт фиксирует состояние, а не решение: пока вопрос здесь,
   соответствующее поведение или выбор технологии не считаются принятыми.
2. Пункт закрывается только вместе со ссылкой на документ или коммит,
   где решение закреплено. Закрытые пункты переносятся в архивную секцию
   в конце файла.
3. Пункт, затрагивающий архитектуру или продуктовые обязательства,
   перед закрытием согласовывается с ответственным участником.
4. Новые пункты добавляй сразу после обнаружения, а не после того,
   как они стали блокером.
5. Для работ, которые уже можно формулировать как задачу (критерии
   готовности, объём), создавай Issue в GitHub и указывай его номер
   в пункте.
